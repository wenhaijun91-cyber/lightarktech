The Ownership Gap

Owning your AI today means being able to build a harness around a model: memory that survives the session, rules it cannot talk its way out of, tools it is allowed to touch, and a way to tell whether it did the job. That is engineering work. Most people will never do it — not because they lack ideas, but because they have no engineers.

We call that distance the Ownership Gap. Our answer is not to teach everyone to build a harness. It is to give them one that is already built — the software equivalent of handing someone a finished house instead of a pallet of bricks.

ArcOS

A model-agnostic harness

ArcOS is built on one principle: perception belongs to the language model, while control, persona, memory and rules belong in hard-coded logic outside it. A five-stage pipeline (perception → strategy → assembly → generation → memory) keeps an AI consistently in character and gives it durable long-term memory — on any backbone (Gemma, Llama, Qwen). Swapping the model is a configuration change, not a rewrite.

Rules that outlive the model

Behaviour is governed by written, versioned rule documents that the pipeline enforces in code rather than by asking the model nicely. When something goes wrong, the fix lands in the rules and stays there — including after the underlying model is replaced.

In production today

Our first product — a 24/7 AI companion for everyday support and reflection — runs on ArcOS and is live on the web and on desktop (macOS, Windows, Linux), with a native iOS app in development. It runs on a dedicated NVIDIA H200 we own and operate.
